## 四、逐项方案

### Bug2 阅读频次重复计数（T0 快修）

- 现象：点击卡片视为一次阅读，再点「开始阅读」又计一次，次数叠加偏大。
- 定位：前端 `src/stores/historyStore.ts`（计数入口）+ 后端 `handlers/library.go` / `services/comic.go`（readCount）。历史曾用 `readCount` 统一替代旧 `clickCount`，疑似迁移后残留旧计数调用点——先 grep `clickCount|readCount` 找重复计数处。
- 修法：统一计数入口 = 进入阅读器成功渲染后 +1（点卡片/进详情不计数）；短窗口幂等（同 gid 短时间窗口内只计一次，防双触发）。
- 验收：连续「进详情 → 开始阅读 → 退出 → 再进详情」只 +1；旧历史数据不追溯修正（口径变更，保留原值）。
- 工作量：约 1 天。

### Bug3 PWA 详情页停留在页面中部（T0 快修）

- 现象：PWA 端点击本子进详情，滑块停留在中部需手动上滑；浏览器无此问题。
- 定位：`utils/scrollMemory.ts`（滚动记忆+回顶）、`router/index.ts`、`utils/detailNav.ts`；`DiagView.vue` 视口诊断面板可复用。
- 疑因：PWA 与浏览器滚动容器不一致（window vs 内部容器），进入详情时「返回恢复位置」逻辑误恢复/未回顶；需 DiagView 真机确认滚动容器归属。
- 修法：详情路由进入时显式强制回顶主容器；区分「用户主动返回」（恢复位置）与「新进入详情」（必须回顶）。
- 验收：iPad PWA 与浏览器两端进入详情均位于顶部；返回时仍能恢复原位置/页码。
- 工作量：约 1 天。

### Bug1 漫画页数顺序错误（T0 先调查后修）

- 现象：已标记到 bug 书架，部分漫画页序错误。
- 定位：`services/metadata.go` / `extract.go` / `scanner.go`（解析与排序）+ `OfflineBookshelf.vue`（展示）。cmd_debug 有 `metadump` / `ziprangecheck` 可取证。
- 第一步先采样：从 bug 书架取 3~5 个样本，确认共性——是压缩包内文件名自然排序问题（1,10,2 应为 1,2,10）、中文字符/特殊字符排序，还是 metadata 解析丢页序；确定乱序发生在「入库时」还是「展示时」（决定改后端 or 前端）。
- 预期修法：全链路统一自然排序（natural sort）。
- 验收：样本全部恢复正确顺序；新增自然排序单测。
- 工作量：调查 0.5~1 天 + 修复 0.5~1 天。

### 优化4 ehentai 链接解析（T1）

- 目标：评论区 ehentai 链接点击直接跳转画廊，免手动复制粘贴。
- 方案：评论渲染层正则提取 `e-hentai.org` / `exhentai.org` 画廊 URL（gid+token）→ 复用 `detailNav.ts` + 详情面板跳转；非画廊链接保持外链。
- 定位：`views/online/OnlineDetail.vue`（评论区）、`utils/detailNav.ts`。
- 验收：评论区任意 ehentai 画廊链接可点击并打开对应画廊详情。
- 工作量：约 1 天。

### 优化6 下载条目查看详情（T1）

- 目标：下载页点击条目查看详情。
- 方案：`DownloadsView.vue` 条目点击 → 复用 `OfflineDetailPanel.vue` + `detailPanelStore.ts`（下载完成即离线漫画，数据已全，仅缺入口）。
- 验收：下载列表任意条目可点击展开/打开详情（含封面、标签、评分）。
- 工作量：0.5~1 天。

### 优化2 忽略标记（T1）

- 目标：更新与查重时支持手动跳过/忽略特定标识。
- 方案：后端新增 `ignored_identifiers` 表（标识 gid/hash + 类型 + 时间，放后端保证 PWA/桌面多端一致）；`OfflineUpdate.vue`（更新检测）与 `OfflineMaintain.vue` / `OfflineCompare.vue`（查重）结果项加「忽略」按钮；维护页提供忽略清单管理（查看/恢复）。
- 决策点：忽略作用域默认全局 + 可恢复（开工前确认）。
- 验收：忽略后对应条目在后续更新/查重中不再出现；可在清单中恢复。
- 工作量：2~3 天。

### 优化3 查重逻辑增强（T2）

- 目标：名称重复判定自动化，减少人工确认弹窗。
- 方案（分层实现，各层独立可测）：
  1. **清洗层**（纯函数）：剥离阿拉伯/罗马数字、第N话、後編/前編/下巻/上巻、DL版、汉化组 Tag → 核心名；
  2. **判定层**：核心名相似度（编辑距离/Token 重合）+ 页数容差（差距 >5 页直接判不同/续集）+ 上传者/画师辅助；
  3. **决策层**：高置信度自动归类 / 中置信度弹窗人工确认 / 低置信度静默，阈值可配置。
- 定位：`services/offline.go`（pairComic）、`views/offline/OfflineCompare.vue`、`OfflineMaintain.vue`；复用 `offline_reconcile_test.go` 等测试样本。
- 防守点：自动归类错比弹窗更糟——阈值保守 + 必须留「纠正入口」。
- 验收：清洗层/判定层有单测；典型样本（同本多语言、续集、后缀版）自动判定准确率达标；误判可纠正。
- 工作量：3~5 天。

### 优化5 搜刮书签（T2）

- 目标：可配置多个书签（首页/tag 搜索两类），边栏快速跳转；例：「上次首页搜刮到此处」、「上次 xx tag 最新到此处」。
- 方案：数据模型 书签（name、kind: home|tag、查询参数快照、anchor: 页码或条目 gid）；存后端 DB（多端同步）；`OnlineSidebar.vue` 加书签分组；首页/搜索结果页提供「存为书签」入口。
- 设计难点：游标加载下定位锚点条目（按 gid 反查页码/offset，或复用日期跳页能力）——开工前需先出细化方案。
- 决策点：书签形态 =「查询+位置快照」与「固定入口」两种都支持（珱垣举例偏前者，细节待确认）。
- 验收：书签可增删改；点击书签恢复搜索参数并定位到锚点；多端一致。
- 工作量：3~5 天。

### 优化1 下载质量升级（T3 大项，单独立项）

- 目标：画廊版（低清）本子快速升级为归档下载方案。
- 已确认边界：**只支持 SakuHentai 自己下载的画廊版**，判定以元数据来源标记为唯一标准（不做文件尺寸自动判定）。
- 方案骨架：入库记录来源标记（gallery/archive）→ 检测存量中 gallery 来源的本子 → 触发归档下载（复用 `download_archive.go`）→ 原子替换本地文件（复用 `comic_refs.go` 引用迁移，保留历史/书架/评分）→ 失败回滚。
- 风险：文件替换时的引用迁移与失败回滚；大文件占用；存量旧数据无来源标记的处理（视为不可升级或手动补标，待细化）。
- 验收：可批量/单个升级；升级后历史/书架/评分完整保留；失败可回滚到原文件。
- 工作量：5 天+（需细化方案评审）。

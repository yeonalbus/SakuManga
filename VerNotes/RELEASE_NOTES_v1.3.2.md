# SakuHentai v1.3.2

> 自 v1.3.1 以来，本版为纯稳定性小更新：根除下载归档反复报错「解压 zip 失败」的重大 bug。实测发现 H@H 归档会话存在下载字节配额，超限后持续返回 404 且旧会话不失效，导致配额永不重置、反复拿到相同随机段直链；zip 校验失败后也无法通过重新下载修复。本版通过「校验失败自动重建归档会话 + 清除 .part/.bits 坏块位图 + EOF 截断字节校验」三重手段彻底收敛，归档下载链路不再翻车。

## ✨ 新增功能

- （本版为纯 bug 修复，无新增功能）

## 🛠️ 优化改进

- 归档分块布局避免 1 字节末块：`total % chunkSize == 1` 时末块退化为单字节 Range，H@H 会返回 206 空 body 被误判为「块不完整」，现自动调整块布局规避
- 归档分块（downloadChunk）与 zip 下载（downloadZip）在 EOF 时校验实际字节数，不足期望长度判定为截断并报错，不再盲目标记完成
- 新增回归测试（分块 EOF 截断校验 / 会话重建缓存清理 / 重建会话重试）与 [`cmd_debug/ziprangecheck`](../backend/cmd_debug/ziprangecheck/main.go) 实测工具

## 🐛 Bug 修复

- 修复下载归档反复报错「解压 zip 失败」且无法通过重新下载修复：zip 校验失败后先重建归档会话（`cancelArchiveSession` invalidate_sessions=1 重置 H@H 下载字节配额）清除旧缓存，再解析全新直链自动重新下载（新增 `retryResolveArchiveDownloadURL`）
- 修复手动 / 自动解锁归档时未清除 `.part/.bits` 分块缓存，位图复用旧会话坏块、即使会话重建后仍校验失败
- 修复 H@H 归档会话下载字节配额超限（404 clocked too many downloaded bytes）后旧会话不失效、配额永不重置，反复拿到相同随机段直链的问题

## ⚠️ 已知问题

- 在线列表负向排除为「本地丢弃」，命中条目较多时单页显示条数变少（游标继续加载）
- 抽卡负向排除后候选数量不足时仅提示，后端采样补位为后续增强
- 跨文件夹在线回填 GID 依赖已登录 IPB 账号，未绑定账号 / 无网络时额外路径无法跨文件夹识别版本
- 项目仍处于快速迭代期，可能存在未覆盖的边缘场景

## 📖 使用说明

- 下载 `SakuHentai.exe` 后双击即可运行（单文件内嵌前后端 + 自定义图标），运行后最小化到系统托盘
- 默认监听端口 `8081`，可在「高级设置」中修改；端口被占用时自动切换空闲端口
- 首次启动自动创建管理员账号 `admin` / `admin123`，登录后请尽快在「安全」中修改
- NAS / 无界面环境请使用 `SakuHentai.exe --headless` 纯后端运行
- 升级安装：直接替换 `SakuHentai.exe` 即可，`manga.db` / `data/` / `config.json` 跟随 exe 目录自动保留；数据库结构由启动时自动迁移，无需手动处理

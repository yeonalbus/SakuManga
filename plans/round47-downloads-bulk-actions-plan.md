# Round47：下载列表批量操作（全部取消 / 暂停 / 恢复 / 解锁 / 重试）

> 状态：**口径已于 2026-10-28 确认；样稿已同步更新；待施工，本阶段不改 Vue / Go 代码。**
> 样稿：`plans/mockups/downloads-bulk-actions.html`（自包含 HTML，双击用浏览器打开即可交互）
> 演示数据：102 条任务（下载中 4 / 排队中 24 / 已暂停 26 / 出错 5 / 锁定 22 / 完成 15 / 已取消 6），每页 8 条；其中 1 条归档任务为「解压失败」，用于演示取消确认的额外警告。
> 起因：用户要求下载列表支持批量操作，并明确按钮只在对应状态视图出现；现有筛选区没有承载批量操作的上下文，因此先重排整页信息层级，再施工。

## 一、已确认口径（逐条对应 2026-10-28 的 8 项）

| # | 决策点 | 确认结论 |
|---|--------|----------|
| 1 | 命名 | 统一为「全部恢复」（对应后端 `resume`），不再使用「全部重启」 |
| 2 | 锁定页签 | 保留独立页签，新增「全部解锁」 |
| 3 | 「全部」页签 | **删除**状态页签的「全部」；用户倾向直接查子类。模式筛选的「全部」（画廊 / 归档维度）保留 |
| 4 | 二次确认 | 操作量 **> 20（即 21 个及以上）** 时：全部暂停 / 全部恢复 / 全部重试 / 全部解锁弹确认；**「全部取消」无论数量多少都弹确认**。20 个及以下直接执行 |
| 5 | 作用范围 | 跨分页生效，处理当前筛选结果的全部任务；**不提供「仅本页」**，不增加心智决策 |
| 6 | 按钮数量 | 按钮上不显示数量；数量只在批量条标题和页签徽标里显示 |
| 7 | 窄屏位置 | 批量条放在页签下方、随页面滚动，**不做底部吸附**（按推荐方案） |
| 8 | 出错 / 锁定 | **不合并**。出错重试不额外消耗 GP；锁定解锁后重新下载会重复消耗 GP，两者代价不同 |

本轮补定的默认口径（如无异议即按此施工）：

- **默认页签：下载中**。页面打开先看当前活动；下载中为空时显示空态，提示切换页签。
- **页签顺序：下载中 → 排队中 → 已暂停 → 出错 → 锁定 → 完成 → 已取消**。活动态在前，终态在后。
- **头部总览保留**：`共 102 个任务 · 活动 81`，其中「活动」= 排队中 + 下载中 + 已暂停 + 出错 + 锁定（不含完成 / 已取消）。删除「全部」页签后，用户仍能从页头看到跨状态总量。
- **模式筛选的「全部」保留**，并在控件前加「模式」标签，明确它和已删除的状态「全部」不是同一维度。
- **单页隐藏分页**：当前页签只有 1 页时不再显示「第 1 / 1 页」。
- **单卡操作**：单卡暂停 / 恢复 / 重试 / 解锁直接执行；单卡取消仍弹确认（与原有行为一致）。
- **单卡解锁不弹确认**：数量为 1，按 > 20 规则无需确认；批量解锁才按数量判断。

## 二、批量按钮与确认规则

| 页签 | 批量按钮 | 二次确认 |
|------|----------|----------|
| 下载中 | 全部暂停、全部取消 | 暂停 > 20 确认；取消始终确认 |
| 排队中 | 全部暂停、全部取消 | 暂停 > 20 确认；取消始终确认 |
| 已暂停 | 全部恢复、全部取消 | 恢复 > 20 确认；取消始终确认 |
| 出错（error） | 全部重试、全部取消 | 重试 > 20 确认；取消始终确认 |
| 锁定（error_lock） | 全部解锁、全部取消 | 解锁 > 20 确认（含 GP 警告）；取消始终确认 |
| 完成 | — | — |
| 已取消 | — | — |

补充：

- 批量条只在**当前页签数量 > 0** 且存在批量动作时出现；数量为 0 直接显示空态。
- 批量条副标题常驻「跨页生效」；若主操作数量 > 20，再追加「操作量较大，执行前会再次确认」。
- 锁定页签的批量条副标题额外常驻「解锁后任务重新排队，会再次消耗 GP」；确认弹窗再用橙色警告区强调「解锁会重复消耗 GP 配额，请确认当前 GP 余额充足」。
- 确认弹窗的按钮色按动作区分：取消=红、解锁=橙、暂停/恢复/重试=蓝；破坏性操作与普通操作一眼可分。
- 全部取消若命中「解压失败」的归档任务，追加红色警告：取消会删除损坏压缩包与半解压文件，下次需要重新下载。

## 三、删除「全部」状态页签后的页面行为

1. **页头**：保留总任务数与活动数；不再提供「全部」混合列表。
2. **默认落点**：下载中；若为空，空态提示「切换上方页签查看其它状态」，模式筛选为画廊/归档时额外提示可切回「全部」模式。
3. **模式筛选**：保留 `模式：全部 / 画廊 / 归档`。这是下载方式的子类，不是状态；与已删除的状态「全部」明确区分。
4. **页签徽标**：7 个页签各自显示数量，直接查子类，不需要先进「全部」再筛。
5. **空态**：不再提供「查看全部任务」按钮（该页签已删除）；改为提示切换页签或模式。
6. **分页**：单页隐藏分页控件；多页时显示「第 X / Y 页 · 共 N 个任务」。
7. **批量条**：只跟随状态页签，不跟随模式；切换画廊/归档时数量与操作范围同步收窄。

## 四、UI 方案（样稿）

### 4.1 层级

1. 页头：标题 + `共 N 个任务 · 活动 M` + 「每 2 秒自动刷新」状态点。
2. 筛选卡：
   - 「模式」分段控件：全部 / 画廊 / 归档；
   - 7 个状态页签（带数量徽标，默认下载中）；
   - 窄屏页签横向滚动，左右渐隐提示还有页签，当前页签居中。
3. 上下文批量条：
   - 左侧：状态图标 + 「排队中任务 24 个 · 全部模式」+ 副标题（跨页 / 操作量确认提示 / 锁定 GP 提示）；
   - 右侧：主操作 + 分隔线 + 「全部取消」红描边；
   - 执行时：spinner + 「正在暂停 24 个任务」+ 进度条 + `3 / 24`；完成后显示 1.5s 结果态。
4. 任务卡片：
   - 左侧状态色条、封面（首字 + 渐变）；
   - 标题右侧状态徽标；错误信息独立成行；
   - 进度条与底栏：优先级内联按钮 + 单条操作（暂停 / 恢复 / 重试 / 解锁 / 取消）。
5. 确认弹窗：动作标题、作用域与跨页提示、按动作着色的确认按钮；取消的损坏压缩包警告、解锁的 GP 警告。
6. 深色 / 浅色主题均适配；窄屏批量按钮一行两枚等宽，卡片底栏上下两行。

### 4.2 视觉语义

- 状态色：排队灰、下载蓝、暂停琥珀、出错红、锁定橙、完成绿、已取消灰。
- 批量按钮：暂停/重试蓝、恢复绿、解锁橙（实心）；取消红描边（始终最后，避免误点）。
- 确认按钮：暂停/恢复/重试蓝、解锁橙、取消红。
- 删除「全部」页签后，页签宽度更紧凑；7 个页签在 1000px 桌面宽度内可完整显示，窄屏横滑。

## 五、交互状态机

```
进入页面
  → 拉取 stats + 当前页签列表
  → 默认 status=downloading，mode=all
  → 该页签数量为 0 → 空态；否则按规则渲染批量条

点击状态页签 / 模式
  → 分页回到第 1 页；按新筛选重新计算按钮组合与数量
  → 数量为 0 → 空态；数量 > 0 → 批量条

点击批量主操作（暂停 / 恢复 / 重试 / 解锁）
  → 若操作正在执行则忽略
  → 数量 > 20 → 弹确认；≤ 20 → 直接执行
  → 执行态：禁用交互、进度反馈、暂停 2s 轮询
  → 完成后 toast 汇总，刷新 stats + 列表，退出执行态

点击「全部取消」
  → 无论数量多少都弹确认（含损坏压缩包警告）
  → 确认 → 执行；取消 → 关闭弹窗

单卡操作
  → 暂停 / 恢复 / 重试 / 解锁：直接执行
  → 取消：弹确认后执行

执行期间
  → 暂停 2s 轮询，避免服务端状态与前端执行态互相抖动
  → 禁用页签 / 模式切换 / 重复点击
```

### 接口建议（样稿不连后端）

- `GET /api/v1/downloads/stats?mode=`：按当前用户权限聚合 7 个状态的数量 + total + active。
- `POST /api/v1/downloads/batch-action`：body `{ action, status, mode }`，服务端按筛选条件逐条执行，返回 `{ affected, failed, skipped, errors }`；复用现有 `PauseTask / ResumeTask / RetryTask / CancelTask / UnlockTask`，取消时沿用 `cleanupCorruptArchive`。
- 批量接口必须逐条复核任务归属和来源状态；确认后若任务状态已变化，计入 `skipped`，前端提示「实际处理 X 个，Y 个状态已变化」。
- 不推荐「前端分页拉全量 ID 后限并发逐条调用」：任务量大时请求数过多，且失败聚合与竞态处理更复杂。

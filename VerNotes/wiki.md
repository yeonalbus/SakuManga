# SakuManga 常见问题（防呆手册）

> 本手册为 SakuManga 用户答疑集合，结构参考 JHenTai Wiki FAQ，内容结合本项目实际功能重写。
> 遇到问题先翻这里；仍无法解决，欢迎提交 Issue（附版本号 + 操作步骤 + 日志/截图）。
>
> 阅读顺序建议：新手先读「一、快速上手」与「三、本地导入」，遇网络问题看「四、网络」，需要用 Docker 部署看「九、Docker 部署」，其余按需查阅。

---

## 一、快速上手（新手必读）

**Q: 我是第一次用，怎么开始？**
1. 下载 `SakuManga.exe`，双击运行（单文件内嵌前后端 + 托盘图标，无需安装）。
2. 浏览器访问 `http://127.0.0.1:8081`（程序一般会自动拉起浏览器）。
3. 首次启动自动创建管理员 `admin` / `admin123`，登录后请尽快在「设置 → 账户」修改密码。
4. 在「设置 → 账户」绑定 E 站凭证后即可浏览在线画廊、下载与阅读。

**Q: 需要自建服务器 / NAS 吗？**
不需要。本质是一个本地 exe，默认只在本机 `127.0.0.1:8081` 提供服务。
- 想手机 / 局域网访问：把监听地址改为 `0.0.0.0`（「设置 → 账户 → 服务器」），同一局域网用 `http://<电脑IP>:8081` 访问。
- 想公网 / 长期运行：部署到 NAS / 服务器，用 `SakuManga.exe --headless` 纯后端模式运行。
- 想在 NAS / 群晖 / 威联通上以 **Docker** 方式部署：见「九、Docker 部署」。

**Q: 双击 exe 后打不开界面 / 不知道访问什么？**
确认浏览器地址栏输入的是 `http://127.0.0.1:8081`（不是 `https`、不是别的端口）。若端口被占用，程序会自动切换空闲端口，日志（或托盘菜单）会提示实际端口。

**Q: 我有一堆本地漫画，怎么导入？**
见「三、本地导入」一节——添加一个总文件夹路径即可，程序自动扫描。

## 二、账号与登录

**Q: 如何绑定 E 站账号？两种方式选哪个？**
「设置 → 账户 → 绑定 Cookie 凭证」弹窗提供两种方式：
- **方式一：账号密码登录**——输入 E 站账号密码，程序自动完成登录并抓取 igneous / sk，**无需打开浏览器复制 Cookie**。遇 E 站验证码 / 风控可能失败。
- **方式二：粘贴 Cookie**——浏览器登录 E 站后，F12 → Application → Cookies 复制完整 Cookie 字符串，**整条粘贴**进输入框自动拆分（形如 `ipb_member_id=xxx; ipb_pass_hash=xxx; igneous=xxx; sk=xxx`），不用逐条填。

**Q: 账号密码登录失败，提示验证码 / 风控？**
E 站登录有人机验证（CF / reCAPTCHA）机制，程序无法绕过。请改用「方式二：粘贴 Cookie」。

**Q: Cookie 过期了怎么办？**
在「绑定 Cookie 凭证」弹窗点「刷新凭证」——程序自动用已填的 `ipb_member_id` / `ipb_pass_hash` 刷新 `sk`（表站）与 `igneous`（里站），无需上站手动抓。

**Q: 登录后只能访问表站，里站看不了？**
确认绑定的凭证含有效的 `igneous`（里站 Cookie）。没有就点「刷新凭证」抓取；账号本身无里站权限则无法解决。

**Q: 能多人共用吗？**
可以。管理员可创建成员账号，分配「下载许可」；每个用户有独立的书架 / 历史 / 评分 / 阅读进度。

## 三、本地导入

**Q: 本地导入是怎么工作的？直接把整个总文件夹填进去就行吗？**
是的。在「设置 → 下载与离线 → 下载 → 额外的画廊扫描路径」添加一个**总文件夹路径**，点扫描即可，程序自动完成以下工作：
1. **自动发现**：递归扫描总文件夹下的所有子文件夹与压缩包；
2. **判定候选**：每个「直接包含图片的文件夹」或「归档压缩包」被视为一本漫画；
3. **解析元数据**：优先读取目录 / 压缩包内的 `metadata` / `ametadata` / `info.json` / `ComicInfo.xml`；
4. **入库**：无元数据也能入库（标题取文件夹名 / 压缩包名），有元数据则补全日文标题、GID、标签、分类等。

**Q: 对文件夹结构有要求吗？**
无强制要求，两种形态都支持：
- **文件夹形态（推荐）**：一本漫画一个文件夹，图片直接放文件夹内（可含子文件夹）；JHenTai / EHViewer 下载的画廊文件夹可直接用。
- **压缩包形态**：`.zip` / `.cbz` 单个压缩包即一本漫画。

**Q: 图片格式支持哪些？**
`.jpg` / `.jpeg` / `.png` / `.webp` / `.gif` / `.bmp` / `.avif`。文件夹内识别到任一种图片即判定为候选。

**Q: 元数据文件有什么用？不填能行吗？**
`metadata` / `ComicInfo.xml` 是**加分项，非必需**：
- 没有：标题用文件夹名，标签为「本地扫描」，无法识别 GID（影响更新检测 / 在线反查 / 查重）。
- 有：自动补全日文原名、GID / Token、标签、分类、发布时间；带 GID 的本子可联网反查补全缺失信息，并参与父子画廊更新检测与查重。

**Q: 导入的注意事项（务必阅读）**
- **推荐形态是文件夹**：项目测试环境基于文件夹形态充分验证。
- **`.zip` / `.cbz` 压缩包**：代码层面支持扫描与阅读，但**测试覆盖不充分**，个别场景（如超大压缩包、特殊命名）可能异常，遇到请反馈。
- **`.rar` / `.7z` 压缩包**：会被扫描识别并入库，但**元数据解析与阅读暂不支持**（仅支持 zip 系），表现可能不完整（标题为文件名、无标签、可能无法阅读）——建议解压为文件夹后再导入。
- **重复导入**：增量扫描会跳过已存在的路径；同 GID 已存在「文件夹形态」时，压缩包形态会自动跳过（避免重复占盘）。
- **来源标签**：添加路径时可填显示名（如「汉化合集」），导入的本子在卡片与详情页会显示该来源角标，便于区分来源。
- **扫描范围**：每个路径可独立开关「离线维护」（参与更新检测 / 查重）与「扫描子文件夹」。

**Q: 导入后没看到本子？**
- 确认路径正确、文件夹内确实有图片（不是套了多层空文件夹）；
- 扫描完成后到「离线模式 → 书架 → 全部离线作品」查看；
- 若提示「结果已过期」，手动点「重新扫描」。

## 四、网络（排障）

**Q: 裸连（无代理）加载失败怎么办？**
在裸连下出现的任何网络问题请自行处理——能访问 E 站 ≠ 程序能访问。请自行准备代理（Clash / v2rayN 等）。

**Q: 我开了代理（Clash「系统代理」模式），浏览器能开 E 站，为什么程序还是连不上？**
**v2.0.1 起已自动处理**：未手动配置代理时，程序会自动跟随系统代理（Windows 注册表）或环境变量 `http(s)_proxy`，Clash 等开启「系统代理」后**零配置直连**。
- 若仍连不上：到「设置 → E 站连接 → 网络」查看「当前生效代理」是否为空。为空说明系统代理未检测到，请手动填写代理地址（如 `http://127.0.0.1:7897`，端口看 Clash 首页）。
- 留空 = 自动跟随系统代理；填写固定地址 = 强制走该代理。

**Q: 为什么列表一直加载失败？显示 Connect Timeout / Receiving Data Timeout？**
- 更换梯子节点等网络条件。
- 节点确实慢时，可在「设置 → E 站连接 → 网络」调大「请求超时时间」（默认 60s）。

**Q: 为什么列表加载失败，显示一大串英文提示？**
这些是 E 站直接返回的访问限制原因（如限流、IP 封锁、需要登录等）。更换梯子节点，或按提示内容自行搜索 E 站官方说明。

**Q: 为什么封面 / 缩略图一直加载失败？**
更换梯子节点。封面走程序内置代理转发，节点到 E 站图片 CDN 不通时即失败；也可直接访问日志里的图片链接确认浏览器能否打开。

**Q: 为什么在线阅读或下载一直卡在「解析」状态？**
- 更换梯子节点。
- 访问里站速度过快会触发 E 站临时限流（短时间所有请求卡住），尝试降低浏览速度 / 下载线程数。
- 尝试只访问表站（「设置 → E 站连接 → EH 网站 → 优先重定向至表站」）。

**Q: 为什么个别图片一直加载中 / 下载中，进度为 0？**
你的网络无法访问到该图片所在的 H@H 节点。更换梯子节点；仍不行可尝试降低下载线程数 / 并发数。

**Q: 提示「IP quota exhausted / quota exceeded」或下载任务进入「锁定」状态？**
E 站 IP / 会话配额耗尽（多用户共用一个节点 IP 时很容易触发）。处理方式：
- 到「设置 → E 站连接 → EH 网站」查看图片配额与 GP / Credits 余额；
- 非捐赠用户配额与 IP 挂钩，更换节点 IP 可重置部分配额；
- 归档任务锁定后，可在 E 站处理配额后点击「解锁重试」（程序会自动校验配额再继续）。

**Q: 提示 509（超出图片配额限制）是什么意思？**
图片配额用完了。配额上限取决于账号 / IP；节点使用人数多时很快耗尽。停止下载，等待配额恢复或更换节点。

**Q: 无法加载画廊，提示 Sad Panda（白屏），网页上却能正常看？**
Sad Panda = 无法访问里站（ExHentai）。
1. 确认账号有里站权限（不知道「里站权限」请自行搜索）。
2. 检查「设置 → 账户」里的 `igneous` Cookie 是否正常：为空或非正常随机字符串时，点「刷新凭证」自动抓取；仍异常则用欧美 IP 重新登录。
3. 使用账号密码登录时，可能登录 IP 已被限制导致抓不到正确 Cookie，改用 Cookie 粘贴方式绑定。
4. 更换梯子节点 / 切换节点地区，直到可用。

## 五、下载与归档

**Q: 下载与归档有什么区别？怎么选？**
- **画廊下载**：逐张爬图，可边下边看；选「原图」时消耗图片配额（可能 509）。
- **归档下载**：E 站官方打包压缩包，消耗 GP / Credits，**不消耗图片配额**，但需下载完成才能看。推荐优先归档。
- 「设置 → 下载与离线 → 下载」可组合选择「画廊 / 归档 × 原图 / 压缩」四种方案。

**Q: 下载任务一直显示「锁定」/ 提示配额不足？**
归档创建需要 GP / Credits，余额不足即锁定。到 E 站兑换 / 等待配额后，在下载列表点「解锁重试」。

**Q: 怎么恢复下载记录 / 让程序重新识别已下载的文件夹？**
程序下载时会写 `metadata` / `ametadata` / `ComicInfo.xml` 到画廊目录。文件还在原路径时：
- 「设置 → 下载与离线 → 下载 → 恢复下载记录」重新登记；
- 或把文件夹加入额外扫描路径，重新扫描入库。

**Q: 下载中断了会从头再来吗？**
不会。画廊下载支持断点续传（`.part` 文件 + Range），归档支持 `.bits` 分块续传；解压失败会清理损坏包并重建会话重下。

**Q: 同一个画廊不小心重复下载了？**
程序会拦截：已下载 / 下载中的画廊入口会提示，不重复入队。若本地已有旧版，可用「维护查重」去重，或用「画质升级」把画廊版升级为归档原图版。

## 六、本地库与维护

**Q: 什么是「画质升级」？**
检测本地由 SakuManga 下载的「画廊版」（低清）资源，一键重新下载「归档原图」并原子替换，历史 / 书架 / 评分完整保留——避免画廊版 + 归档版重复堆积占盘。

**Q: 为什么有些本子标题是英文，不是日文原名？**
本地画廊入库时会保存日文原名（`titleJpn`），展示优先日文；仅当元数据里没有日文标题（E 站本身无 #gj 字段）时才用英文。离线详情页可「修改标题」手动指定，清空输入即恢复首次入库的日文原名。

**Q: 怎么查重？「疑似重复」是什么？**
「离线维护 → 维护查重」按 GID 精确 + 名称级模糊比对；多语言版本 / 重传补档 / 版本变体会被聚为「疑似重复」簇，**只给建议不自动删除**（后端没有任何自动处理路径，设置里也无自动开关），可进双列对比页人工确认。

✂️ **怎么处理疑似重复？** 三种删除入口：① 组内成员卡片右上角勾选若干本 → 顶部工具栏「批量删除（保留文件 / 含文件）」一键提交；② 成员卡片底部「删除（保留文件）/ 删除（含文件）」单本删除；③ 进入「成员对比」页，左右面板头部「🗑️ 删除此成员」。三种入口都会**即时重算**该组：组内仍有 ≥2 本 → 继续显示（成员数收缩）；只剩 1 本 → 视为处理完毕，该组自动从列表消失（无需重新扫描）。删除后剩余成员不足 2 本时，对比页顶部会提示「该组已处理完毕」，并把被删成员原位置换成占位页（便于回看刚删了什么）。

🔒 为避免误删，疑似重复区**每组至少保留 1 本**：某组已勾选到「成员数 − 1」本时，最后一本的勾选框会自动禁用（取消同组其他勾选即恢复可选）。想误判剔除而非删除时，仍可用「忽略本组 / 忽略所选成员」（可随时从忽略清单恢复）。忽略 / 恢复 / 删除操作均已即时生效，无需再重新扫描一遍。

**Q: 为什么维护查重每次进页面都会自动扫描？**
v2.0 起已改为「不自动扫描」——检测到书库变更只提示结果过期，由你手动点「重新扫描」，避免每次进入触发数十分钟的全量联网核对。

**Q: 合订本几百页，要一页页翻吗？**
不用。阅读器支持章节配置 / 大纲侧栏 / 页面收藏，从目录直接定位章节。

**Q: 书架排序乱了，能自定义吗？**
可以。书架列表与书架内项目都支持拖拽排序、「移动到第 X 位」「快捷置顶」，顺序持久化到后端。

**Q: 手机（PWA）怎么用？**
浏览器访问程序地址后，「添加到主屏幕」即可像 App 一样使用（需部署到可访问的地址，如局域网 IP 或内网穿透）。PWA 端阅读进度 / 书架 / 历史与桌面端云端同步。

## 七、设置

**Q: 为什么列表里没有标签 / 语言 / 页数，感觉空荡荡的？**
在线列表的标签数量取决于 E 站账号的「列表样式」设置：E 站官网把列表样式改为能显示标签的布局（如 Compact 外的布局），程序才能解析到完整标签。注意若开了「优先重定向至表站」，表站和里站的列表样式都要改。

**Q: 网页端和 SakuManga 想用不同的 E 站设置（Profile）？**
在 E 站官网 uconfig 页面创建多个 Profile，再到「设置 → E 站连接 → EH 网站 → Profile 设置」勾选程序使用的那个 Profile。

**Q: 为什么搜索结果比网页上少 / 没有数据？**
1. 检查筛选条件：「设置 → 阅读体验 → 偏好」与搜索框旁的筛选抽屉（分类 / 语言 / 评分 / 负向排除是否误选）。
2. 检查 E 站账号自身是否有过滤设置（我的标签屏蔽等，见 uconfig）。

**Q: 「优先重定向至表站」是什么？**
- 非限制性画廊表站 / 里站均可访问；限制性画廊对非捐赠用户仅里站可访问。
- 里站连接比表站不稳定，并发多时容易全部中断。
- 开启后：进详情页优先用表站链接，失败（限制性画廊）再兜底切里站。

**Q: 为什么按日期跳转后，画廊时间看起来不对？**
E 站按 UTC 存储时间，程序按系统时区展示，存在时区差。检查系统时区设置是否正确。

## 八、其他

**Q: 能导入其他阅读器（JHenTai / EHViewer 等）的数据吗？**
程序间数据格式不互通。但 SakuManga 兼容读取 E 站官方 `metadata` / `ametadata` / `ComicInfo.xml` 元数据：把 JHenTai 等下载的文件夹加入扫描路径后重新扫描，可自动识别 GID / 标签 / 日文标题等元数据（缺失信息可联网反查补全）。

**Q: 标签中文翻译 / 联想数据哪来的？**
标签汉化来自 EhTagTranslation 社区数据库，联想来自 e-hentai-tag-count，均在「设置 → 标签管理 → Tag 维护」中同步更新；数据遵循 CC BY-NC-SA 3.0，仅供学习交流。

**Q: 标签怎么一直是英文？「开启标签中文翻译」开关点不动？**
1. 标签汉化由「词典」驱动（`设置 → 标签管理 → Tag 维护` 里可看到版本号）。词典没下载成功 / 还在下载中时，标签会以英文原文显示——点同步按钮（🔄）等它下载完成即可。容器部署请注意 `data/` 目录要可写、且容器能访问 GitHub。
2. 该开关控制的是**服务端**翻译总开关，点击即保存（写入 `config.json` 的 `tagEngine` 段），刷新后保持；关闭后全站标签立即回原文显示。
3. 若「Tag 维护」面板提示词典加载失败，可点同步按钮重试，或直接刷新页面。

**Q: 如何反馈 Bug？**
请带上：**版本号**（「设置 → 关于软件」）+ **操作步骤** + **截图或日志**（「设置 → 日志」可查看 / 导出）。反馈越具体，修复越快。

**Q: 数据存在哪里？升级会丢数据吗？**
`manga.db`（数据库）/ `data/`（标签数据）/ `config.json`（配置）都跟随 exe 目录存放。升级安装**直接替换 exe 即可**，数据自动保留；数据库结构由启动时自动迁移，无需手动处理。

## 九、Docker 部署

> **官方镜像（自 v2.1.1 起提供）**：`ghcr.io/yeonalbus/sakumanga`，同时提供 `linux/amd64` 与 `linux/arm64`（群晖 / 威联通 / 树莓派 / Apple Silicon 都能直接跑），由 GitHub Actions 在推送 tag 或手动触发时自动构建发布，适合 NAS / Linux 服务器等长期运行场景。
>
> ⚠️ **诚实说明**：项目作者本地没有 Docker 环境，镜像由云端 CI 构建、**未经作者本机实测**；若在启动、挂载或架构上遇到问题，欢迎在 Issue 反馈（附 `docker logs` 输出），会尽快修复。不用 Docker 的用户，Windows 单文件 `SakuManga.exe` 仍是官方推荐方式。

**Q: 用官方镜像部署（推荐，最省事）**

```bash
docker pull ghcr.io/yeonalbus/sakumanga:2.1.1

docker run -d --name sakumanga --restart unless-stopped \
  -p 8081:8081 \
  -v /volume1/docker/sakumanga:/app \
  ghcr.io/yeonalbus/sakumanga:2.1.1
```

访问 `http://<NAS_IP>:8081`，首次启动自动创建管理员 `admin` / `admin123`，登录后请尽快在「设置 → 账户」修改密码并绑定 E 站凭证。

容器内的程序以 **`--headless`（纯后端）模式**运行——该参数已写进镜像启动命令，`docker run` 时无需自己添加。`-v` 指定的目录是数据目录（不显式挂载时数据落在匿名卷里，不易管理）：`manga.db` / `config.json` / `data/` / `logs/` 都会落在其中。

**Q: 官方镜像有哪些标签？怎么升级？**
- 标签：`2.1.1`（精确版本，**生产建议用这个**）、`2.1`（同 minor 最新）、`latest`（最新发布）
- 升级三步（数据在挂载目录里，不受影响）：

```bash
docker pull ghcr.io/yeonalbus/sakumanga:2.1.1   # ① 拉新版本（换成新版号）
docker rm -f sakumanga                          # ② 删掉旧容器
# ③ 用上面同样的 docker run 命令重新启动（只改标签）
```

用 `docker-compose.yml` 更省事（升级只改一行 tag，再 `docker compose up -d`）：

```yaml
services:
  sakumanga:
    image: ghcr.io/yeonalbus/sakumanga:2.1.1
    container_name: sakumanga
    restart: unless-stopped
    ports:
      - "8081:8081"
    volumes:
      - ./sakumanga-data:/app
    environment:
      - TZ=Asia/Shanghai
```

**Q: 镜像会随版本更新吗？里面是哪个版本？**
- **推送 `SakuManga-X.Y.Z` tag 时会自动构建并推送镜像**；也可以在仓库 Actions 页面手动触发（左侧选 `Docker Image (GHCR)` → Run workflow）
- 镜像从仓库源码构建，构建标识会注入「设置 → 关于软件」，可核对来源
- 一次构建同时产出 `linux/amd64` 与 `linux/arm64` 两种架构

**Q: 不想用官方镜像，想自己构建？**

仓库已自带 `Dockerfile`、`docker-entrypoint.sh`、`.dockerignore`，两种方式任选：

- **Windows 本机（已装 Docker Desktop）**：双击 `build-docker.bat` 构建并载入本地镜像供测试；`build-docker.bat push` 则构建多架构并推送到 GHCR（需先 `docker login ghcr.io`）
- **命令行**：

```bash
# 单架构本地构建（可立刻 docker run 测试）
docker build -t sakumanga:dev .

# 多架构构建并推送（需先 docker login ghcr.io -u <你的用户名>）
docker buildx build --platform linux/amd64,linux/arm64 \
  -t ghcr.io/<你的用户名>/sakumanga:dev --push .
```

镜像构建阶段**不需要 Node**——后端是纯 Go，且 `backend/webui/dist`（前端产物）已随仓库维护。若要连前端源码一起改，先在本地 `npm run build` 并把根目录 `dist/` 拷进 `backend/webui/dist/`，再构建镜像。

仓库中这两个文件的实际内容如下，便于你理解或自行改造：

`Dockerfile`：

```dockerfile
# ── 构建阶段：仓库已入库 backend/webui/dist（前端产物），无需 Node ──
FROM golang:1.26-bookworm AS build
WORKDIR /src
COPY backend/go.mod backend/go.sum ./
RUN go mod download
COPY backend/ ./
RUN CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o /SakuManga .

# ── 运行阶段 ──
FROM debian:bookworm-slim
RUN apt-get update \
 && apt-get install -y --no-install-recommends ca-certificates tzdata \
 && rm -rf /var/lib/apt/lists/*
ENV TZ=Asia/Shanghai
COPY --from=build /SakuManga /opt/SakuManga/SakuManga
COPY docker-entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
WORKDIR /app
EXPOSE 8081
ENTRYPOINT ["/entrypoint.sh"]
```

`docker-entrypoint.sh`：

```sh
#!/bin/sh
set -e
# 程序会把 manga.db / config.json / data / logs 落在自身所在目录，
# 因此二进制每次启动复制到数据目录 /app，数据全部留在挂载卷里。
cp -f /opt/SakuManga/SakuManga /app/SakuManga
chmod +x /app/SakuManga
exec /app/SakuManga --headless
```

**Q: 不想用 Docker，NAS 上还有别的办法吗？**

有。在任意一台机器上交叉编译出 Linux 版二进制，拷到 NAS 直接运行，功能与镜像完全一致：

```bash
cd backend
# Windows cmd：
set GOOS=linux & set GOARCH=amd64 & go build -o SakuManga-linux .
# PowerShell：
# $env:GOOS="linux"; $env:GOARCH="amd64"; go build -o SakuManga-linux .

./SakuManga-linux --headless
```

arm64 的 NAS（群晖 ARM 机型、树莓派等）把 `GOARCH` 换成 `arm64`。这条路的代价是要自己保证 CA 证书、时区与目录权限（镜像里这些已经装好）。

**Q: Docker 部署要注意什么？**
- **数据持久化**：`manga.db`（含 SQLite 的 `-wal` / `-shm` 文件）、`config.json`、`data/`（标签库缓存）、`logs/` 全部落在挂载卷 `/app` 里，删除 / 重建容器不丢数据。**不要把数据目录里的文件单独挂载**（例如只挂 `manga.db` 单文件），否则 SQLite 的 `-wal` 文件留在容器层，重建容器可能丢数据；整目录挂载最稳。
- **升级**：见上文「官方镜像有哪些标签？怎么升级？」——换镜像标签重建容器，或 `docker compose up -d`；数据保留。自己构建的镜像同理，`docker rm -f` 旧容器后用新镜像启动。
- **代理**：容器内访问 E 站若超时，在「设置 → E 站连接 → 网络」里**显式填写宿主机代理**（如 `http://172.17.0.1:7897`；群晖 / Macvlan 场景用宿主局域网 IP）。设置页留空时程序会尝试跟随「系统代理」，而容器内探测不到宿主系统的代理设置，因此建议手动填。
- **首次启动会联网**拉取标签库（来自 GitHub，落在 `data/` 下）：容器无网络时不影响启动，只是标签汉化 / 联想为空，可稍后手动同步。
- **改前端源码后再构建镜像**：先在本地 `npm run build` 并把根目录 `dist/` 拷进 `backend/webui/dist/`（镜像构建阶段不含 Node）。
- **构建上下文**：仓库自带的 `.dockerignore` 已排除 `node_modules`、`dist`、`.git`、`Test`、`MangaExamlpe`、`Server`、`manga.db*`、`*.exe` 等；**注意不要排除 `backend/webui/dist`**，镜像构建依赖它。
- **PWA 加到手机主屏**需要 https（局域网直接 http 访问不行），建议套一层反向代理并配证书。
- **权限**：首次运行会向挂载目录写入数据库与缓存，确保容器对 `/app` 有写权限（Linux 下注意目录属主）。
- **端口冲突**：容器内固定监听 `8081`，宿主机端口用 `-p 8081:8081` 左侧改写（如 `-p 18081:8081`）。

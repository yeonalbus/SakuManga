# SakuManga v2.2.0

> 自 v2.1.1（2026-09）以来共 67 个提交，本版主题是**本地库维护查重的算法与界面重构**：离线查重从 Tier 1 单字段升级为「双字段池 + 方括号版本标记 + 作者硬否决 + 多字段打分分档」，名称级疑似重复由 10 簇提升至 82 簇（标定集正样本召回 16/16、负样本误报 0）；维护页重写为「按差异分组的可清零待办」并新增忽略清单独立页，忽略语义升级为「直到有变化为止」。副线是**书架利用率**（书架墙总览页 + 整架导入阅读清单 + 手动指定封面）与**搜刮书签可用性**（拖动排序 + 失效检测 / 时间锚自动迁移），另含一轮体验与性能修复。数据库结构由启动时 AutoMigrate 平滑迁移，升级仅需替换 exe 或换镜像标签。

## ✨ 新增功能

- **书架墙总览页**（`/offline/bookshelves`）：封面网格 + 顶部统计条「N 个书架 · 收藏 M 本 · 未读 K 本」；支持未读过滤 / 名称搜索 / 排序（自定义拖拽 · 未读最多 · 本数 · 名称）；卡片 hover 可直接置顶 / 重命名 / 删除；封面取架内展示顺序第一本，无封面回退首字占位砖
- **书架未读可视化**：侧栏「全部书架」改为跳转书架墙；置顶书架的徽标改为「未读 / 总」（未读清零转绿显示 `N ✓`）；书架折叠区底部新增「📖 未读 N 本」一键跳转并自动过滤；后端 `GET /bookshelves` 新增 `unreadCount` / `coverUrl`
- **整架导入阅读清单**：按书架展示顺序把整架作品**增量追加**到本地阅读清单末尾（已在清单中的自动跳过，导入后留在书架不跳转）；书架墙卡片与书架页头部各一个入口，空书架置灰，toast 反馈「已导入 N 本（跳过 M 本）」
- **手动指定书架封面**：新增封面选择浮层（架内本子缩略图点选 + 「↺ 恢复自动封面」）；优先级为「手动指定 > 架内第一本 > 首字占位」；本子被替换时封面引用自动迁移，被删除时回退自动封面
- **搜刮书签拖动排序与分段收纳**：常驻前 6 条平铺 + 「⋯ 其余 N 条」**原位内联展开**（展开后限高滚动，不再顶掉下方分组）；左侧图标位 hover 扩为「⠿ 拖动 / ✕ 删除」操作区，触摸设备把手与删除常驻；新建书签追加末尾，老库升级后顺序不变
- **书签失效检测与时间锚自动迁移**：新增批量探测——已删除 / 版权下架（410 / 403）、gid 不存在（200 空详情）、被新版本取代、正常（顺带刷新标题与发布时间）；侧栏提供手动全量检测与带角标的清理入口；失效书签持久化 ⚠️ 标记 + 划线 + 原因提示。已删除或被取代的书签改用**时间锚迁移**（按发布时间 `seek` + 翻页寻找同时刻最近画廊，迁移前弹窗询问），实测偏差 0 分钟、1 页命中；锚点不可恢复则保留位置快照
- **在线详情页「📚 本地」按钮**：在线画廊已存在本地副本时，动作栏（桌面 + 移动）的「⬇️ 下载」替换为「📚 本地」，点击直达本地画廊详情（本地副本 ID 三级兜底：后端 `localId` → 本地优先缓存 → 离线列表按 GID 反查）
- **「加载较新内容」滚动锚定**：加载前置插入后，锚点卡**像素级原地不动**（记录偏移 + 布局稳定后平移 `scrollTop`），并加脉冲金框标记「新内容边界」；首页 / 订阅 / 收藏夹三处统一接入
- **离线查重算法升级（Tier 1）**：指纹改为**双字段池**（`title_jpn` 优先、`title` 兜底，任一字段同键即成组）；版本标记正则允许方括号（`[無修正]` / `[中国翻訳]` / `[DL版]` 等）并清理空括号残留；词表补充中文方头括号 `【】` 与常见汉化标记；新增**作者硬否决**（双方 `artist` 非空且不等则绝不判重）——簇数 10 → 73
- **离线查重算法升级（Tier 2 近似层）**：blocking（作者关系 + 同卷号 + 页数差 ≤5 + 核心名 token 交集）+ 多字段加权打分 + 高 / 中 / 低分档（低档折叠）；关键判据是**正文相似度硬门槛、括注相似度只加分不扣分**（只看整体相似度时任何阈值都无解）——簇数 → 82，正样本召回 16/16、负样本误报 0/16
- **维护结果持久化 + 本地判重先行**：新增单行快照表，进入维护页**立即展示上次结果（秒开、不阻塞）**，后台再增量检测与判重，联网核对结果渐进更新；不必每次重扫
- **联网复核设置项**（默认关闭）：开启后仅对非高置信簇用归一核心名走 E 站反查校验，命中同标题升为高置信，未命中标注「联网复核未确认」；遵守任务暂停 / 取消检查点，未绑定 IPB 账号时静默跳过
- **忽略升级为「直到有变化为止」**：忽略条目记录忽略当时的成员集合——成员全在快照内则静默，出现快照外的本子则照常列出并标注「此前已忽略 · 新增 N 本」，点「确认新增」纳入快照后继续静默；升级时自动幂等回填存量快照
- **维护界面 v3 重构**：页头收敛为「重新扫描 + ⋯ 更多」；待办进度条 + 高 / 中置信计数；疑似重复按「两本差在哪」分 6 类折叠分组（高度相似 / 语言版本不同 / 体积差异 / 页数差异 / 去码不同 / 三本及以上，默认只展开「高度相似」）；差异标签不进对比页即可判断，组内可就地展开对比；舒适 / 紧凑两种密度；窄屏可用（成员竖排、对比上下堆叠）
- **忽略清单独立页**（`/offline/ignore`，管理员）：条目可折叠展开成员卡片（含「同组 / 未构成重复组」标注），失效条目可清理，支持「确认新增」与「恢复忽略」
- **疑似重复支持删除**：成员卡右上角固定勾选框 + 底部单卡删除，区标题下内嵌批量删除工具栏（独立于「建议删除」区勾选态），对比页左右面板可就地删除并**原地占位**（索引不跳动）；某组删至剩 1 本自动从列表消失，无需重扫。红线保持：**永不自动删除、永不自动忽略**
- **维护页成员卡信息增强**：显示 E 站质量决策标签（渣翻 / 外部广告倾向删除 · 马赛克修正看情况 · 无修正倾向保留）、成员级画师、固定 4 行布局（同组卡片按钮对齐；语言缺失与无标题均有占位显示）
- **离线本地搜索覆盖日文原名**：本地关键词检索按卡片上看得见的标题（`titleJpn` 优先）匹配，顶栏搜索与筛选抽屉两处关卡统一；离线抽卡 / 推荐的正向、词条队列与负向关键词同步补齐
- **Tag 中文化设置持久化**：新增 `GET/POST /api/v1/tags/settings`，「开启标签中文翻译 / 标签补全排序规则」两个开关落到配置文件并即时生效（关闭后立即回原文，无需刷新）
- **其他**：阅读器页码角标改为**翻页闪现 1.5s 后淡出**（不再常驻挡字）；封面缓存按**最后访问时间**自动清理（命中即续期，回收 7 天未访问文件，后台每 6 小时一轮）；书架折叠状态本地记忆

## 🛠️ 优化改进

- **查重内容签名缓存**改以「目录 mtime 与上次算出签名时相等」为判定基准，维护不再每次递归遍历全部文件夹（旧判定实机仅 3.6% 命中，机械盘 / 网络盘收益明显）
- **日志 tail 接口**改为从文件尾部反向分块读取 + `limit` 安全阀（尾窗 300 行：1455µs → 402µs，alloc 1585KB → 138KB）
- **维护页去码判定**改以官方 `other:uncensored` 标签为准、标题关键词降为兜底，并合并「扫描解析」与「Tag 维护刷新」两来源标签（覆盖 115 → 537 本），中文 tag 覆盖同步提升
- **书签标记与失效复核**限定在创建时的搜索 & 筛选条件作用域内，避免切换条件后标记错位或误判
- **侧栏排版统一**：书签组紧跟历史记录、间距与相邻链接对齐，书签与书架抽屉标题排版一致
- **在线列表加载**返回 `{added, hasMore, error, skipped}` 供书签定位循环判停，新增失效标记清除接口（修复一次定位失败后角标永久残留）
- **配置文件写入**改为读-改-写，避免保存代理设置时清掉其它字段（如标签引擎设置）

## 🐛 Bug 修复

- **日志监控终端长时停留卡死**：改自增 id key + 首屏只取尾部 300 行 + 贴底跟随（用户上翻不被拽回）+ 页面隐藏自动停轮询（有头 Chrome CPU ≈1.4 核 → ≈0.15 核，首屏响应体 2026KB → 35KB）
- **标签中文翻译失效**：App 挂载时在登录页就请求需鉴权的词典接口，401 后不再重试，导致整个会话标签显示英文、必须整页刷新才恢复——改为认证态驱动加载 + 失败退避重试
- **标签开关「假开关」**：两个开关此前只有前端状态、没有写入接口，点击后刷新即弹回——现接入后端持久化并在失败时回滚
- **离线搜索结果不全**：修复只匹配 `title` 导致日文原名列作品搜不到的问题（实测搜「極東絢爛賭博島ドリームアイランド」只出 1/5 本；全库 24.5% 作品 `titleJpn != title`）
- **iPad 竖屏阅读器**全局汉堡按钮遮挡返回按钮（阅读器内隐藏全局汉堡）
- **书架墙封面与占位首字重叠**（改加载状态机 + 校正层叠顺序）
- **被新版本取代的书签**不能直接替换 gid（新版本发布时间与列表位置都不同），改与失效统一走时间锚迁移
- **维护页三处**：三本组展开对比渲染崩溃、新增感知假阳性（组级与成员级画师不一致时误报）、升级后存量忽略条目集体复活（启动时幂等回填快照）
- **对比页误报文案**：命中「簇存在但成员不足 2」时不再误报「结果可能已刷新，请重新扫描」

## ⚠️ 已知问题

- **「加载较新内容」锚点卡列位可能横跳一格**：E 站每页固定 25 张，4 / 3 / 2 列时 25 不整除，新页最后一行与旧页首行混排所致——锚点卡的**垂直位置精确保持**，但列位会变。彻底消除需页边界强制换行（代价是每页末行留空 + 顶部孤卡），已确认接受现状
- **首次进入维护页会多出约 70 组待确认**：这是查重算法升级（10 簇 → 82 簇）带来的预期行为变化，不是异常；后续同样只会在算法或库内容变化时出现
- **忽略 / 恢复 / 确认新增响应约 2~3 秒**：三者都会触发后端名称级簇同步重算（实测约 3 秒），前端有 toast 提示与列表刷新
- **`title_jpn` 缺失或为脏数据时仍可能漏检**：查重不做内容抽页，证据仅限元数据，「标题完全不同且无 gid 关系、页数也不同」的同类作品抓不到
- 疑似重复的删除**直接作用于本地库**（可勾选是否连同文件一起删），请确认后再操作；项目**永不自动删除、永不自动忽略**
- 项目仍处于快速迭代期，可能存在未覆盖的边缘场景

## 📖 使用说明

- **Windows exe**：下载 `SakuManga.exe` 双击运行（单文件内嵌前端 + 后端 + 自定义图标），运行后最小化到系统托盘，右键托盘图标可选「打开界面 / 退出程序」
- **Docker（推荐 NAS / Linux 长期运行）**：

  ```bash
  docker run -d --name sakumanga --restart unless-stopped \
    -p 8081:8081 \
    -v /your/data/dir:/app \
    ghcr.io/yeonalbus/sakumanga:2.2.0
  ```

  镜像同时提供 `linux/amd64` 与 `linux/arm64`，标签策略 `2.2.0` / `2.2` / `latest`；数据（`manga.db` / `config.json` / `data/` / `logs/`）全部保存在挂载目录，升级 = 换标签重建容器。完整说明见 [`VerNotes/wiki.md`](../VerNotes/wiki.md)「九、Docker 部署」
- **纯后端（NAS 无 Docker 环境）**：`SakuManga.exe --headless`
- 默认监听端口 `8081`（「设置 → E 站连接 → 网络」可改），被占用时自动切换空闲端口
- 首次启动自动创建管理员账号 `admin` / `admin123`，登录后请尽快在「账户」中修改
- 升级安装：exe 方式直接替换文件；Docker 方式换镜像标签重建容器。数据均自动保留，数据库结构由启动时自动迁移（本版新增书签排序权值、书架封面引用、查重签名缓存、忽略成员快照、查重设置等列与两张单行表，均为平滑迁移）
- 本版维护页首次进入会列出较多待确认的疑似重复（算法升级所致），可按「两本差在哪」分组逐个处理，或对确认无问题的组点「都留（不再提示）」

## 👤 珱垣要做的（产品 & AI 经理）

**日常，每个 Round**

| 时机       | 珱垣要做的事                                         |
| -------- | --------------------------------------------- |
| 提需求时     | 跟AI讨论分歧 → 定稿口头或写进 `YeonPlans/`（AI只读）            |
| AI交付后     | **实机验证**——这是唯一只有珱垣能做的：浏览器/iPad/手机真手感，AI只有单测和构建 |
| Round 收尾 | 花 1 分钟扫一眼 `YeonBriefs` 新增那节，看AI记的事实对不对、有没有漏    |

**发版时，收到AI的简报后**

1. 拍版本号（AI给建议，珱垣定）
	- **版本号规则**：
		- MINOR 含新功能（2.3.0）；
		- PATCH 仅修 Bug（2.2.x）。
		- 未发布的版本号若被后续内容吸收，不单独发版。

2. 从AI的 2~3 句候选里挑/重写**本期主题**

3. 改 README 的「当前状态」+「后续计划」

4. 用简报做底稿，写 GitHub Release 正文
	- **发版通知**：
		- AI 在简报定稿时主动告知「可以发版了」并给出简报路径（`DSPlans/YeonBriefs/BRIEF_vX.Y.Z.md`），珱垣不必自己盯版本节奏。

5. 在 GitHub 网页创建 Release、上传 exe、点发布

6. （可选）换 README 预览图

**发布后**

- 贴文宣传、答反馈、筛 issue 转给AI
- 决定 `wiki.md` 要不要补条目（补写归AI，决定归珱垣）

**随时**

- 要改 `YeonPlans/` 里任何文件，**明确说出文件名给AI授权**，否则AI不碰

## 🤖 AI做的（对应位置）

|---|---|
|每 Round|计划落档 → 实现 → 单测/构建 → 增量写 `YeonBriefs`|

|发版中|commit + tag + push，盯 Actions 镜像|

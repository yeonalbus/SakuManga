# SakuManga v2.3.0

> 自 v2.2.0（2026-09）以来共 44 个提交。本版是**双主线**：**搜刮书签重做**——从侧栏平铺列表升级为独立书签页（`/online/bookmarks`）+ 书签级每日更新探测，书签获得三标记（追新 / 续扫 / 兴趣）、备注、置顶、已囤货，失效检测与拖动排序退场，改为锚点缺失时按发布时间自动迁移续定位；**下载链路升级**——无界待调度队列 + 统一调度器（修复实机 704 任务卡死）、下载列表批量操作、高级代理（Clash / mihomo 控制面）与归档节点联动重试。另含**全站约 550 处 emoji / 符号替换为 Phosphor 矢量图标**、订阅页 `/watched` 路径修复、E-H tag 别名脏数据自愈。数据库由启动时 AutoMigrate 迁移 + 书签字段一次性幂等回填，升级仅需替换 exe 或换镜像标签。

## ✨ 新增功能

### 搜刮书签

- **书签独立页**（`/online/bookmarks`）：三列名片墙（1100px 降两列、720px 降单列），置顶区（最多 5 条）与普通区以分隔线区分；每张卡固定四区——封面 / 标题 / 标记徽章 / 备注框（76px ≈ 3 行），有更新时卡片加金色框
- **书签三标记**：`role` 取 `newest`（追新，蓝）/ `oldest`（续扫，绿）/ `interest`（兴趣，灰），以卡片左侧 3px 竖色条区分；老书签迁移时按原名称自动识别回填（含"最旧""最新"与"已下载完"）
- **每日自动更新探测**：服务端调度器按标签维护设置的刷新时刻（`TagMaintainSetting.RefreshHour`）触发，遍历各用户绑定凭据，对 `updateWatch=true` 的书签各取一页列表（不带 seek / next），判据 `首条 postedAt > anchor.postedAt` → `hasUpdate=true`；探测失败只写 `updateError`、不清红点。页面顶部另有「检查更新」手动触发（`POST /scrape-bookmarks/probe`，可指定 ids）
- **侧栏书签组重做**：无折叠；标题点击进书签页；常驻「更新探测」按钮 + 最多 5 条置顶书签，点击沿用原「跳转 + 恢复筛选 + 脉冲定位」链路
- **书签字段扩展**：`Note`（备注，3 行输入框、按折算显示行数校验）、`Pinned`（置顶）、`BulkDone`（已囤货）、`UpdateWatch` / `HasUpdate` / `UpdateCheckedAt` / `UpdateError` 落库；创建弹窗可配置 role / 备注 / 更新开关 / 已囤货
- **创建时锚点转移提示**：若已存在同检索条件（signature）的书签，创建前提示可转移，不自动替换
- **失效检测退场**：删除原「失效检测 / 清理失效」（`scrape_bookmark_check.go` 及前端检测编排、`/check` 路由、`anchor.invalid` 字段读写）；改为锚点找不回时**按发布时间自动迁移并续定位**（迁移成功写库后自动 `beginLocate` + `runLocate`）

### 下载链路

- **无界待调度队列 + 统一调度器**：原容量 256 的待执行 channel 满即丢弃，批量加入 700+ 任务后任务永久停在「排队中」；现改为无界队列 + 统一调度器（`download_queue.go` / `download_scheduler.go`），任何排队任务必达调度器；等归档并发窗口与全局 10 线程配额的任务改为**非阻塞预留**，留在队列而非占住执行协程
- **下载列表批量操作**：7 个状态页签（带数量，默认「下载中」）+ 模式分段，支持**全部取消 / 暂停 / 恢复 / 解锁 / 重试**；跨分页作用于当前筛选结果；超过 20 条才二次确认，「全部取消」无论数量都确认（出错 + 非纯画廊模式时附损坏压缩包警告）；批量解锁按任务发起者分组，每组只请求一次 `/eh/status` 校验 GP 后逐任务取消旧归档 Session、清缓存并重新入队（`download_batch.go`、`GET /downloads/stats`、`POST /downloads/batch-action`）
- **高级代理设置（管理员）**：`NetworkSetting` / `ArchiveBinding` 两张新表 + `GET/POST /network/advanced`、`POST /network/clash/test`、`GET /network/clash/groups`；对接本机 Clash / mihomo 控制面（独立无代理 Transport，含 401 / 不可达 / 组不存在 / GLOBAL 保护），按站点（画廊列表 / 归档下载 / E-H）配置代理组；保存时控制面不可达仅告警、组不存在或选 GLOBAL 拒绝保存
- **归档失败换节点重试**：阶梯 0 原地重试（300 / 900ms）→ 阶梯 1 换节点（全组延迟测试、过滤假节点、取前 5 候选，切换后**必须重置连接池**，成功则写绑定）→ 阶梯 2/3 判错与画廊级连续失败熔断（窗口 3）；扣费后写 `ArchiveBinding`（20h TTL），重试时**先切回原节点再报价**以省 GP 重复扣费；出口 IP 探测异步、失败静默；任务卡显示所用节点名（`DownloadTask.NodeName`）
- **代理 Secret 只写不回传**：`GET` 只返回 `hasSecret`，保存时 `keepSecret=true` 沿用原值；测试连接自动沿用已保存密钥

### 界面与图标

- **全站矢量图标**：新增 `src/components/icons`（`AppIcon` 封装 + 语义图标映射，基于 `@phosphor-icons/vue`），替换组件 / 页面中约 550 处用户可见 emoji 与符号（`✕ ‹ › ❯ ▲▼ ⠿ « »` 等）；普通位置用 regular 空心，收藏 / 书签 / 清单 / 已下载 / 更新探测 / 置顶 / 忽略 / 在线等**状态位激活时切 fill 实心**并沿用状态色；注释内 emoji 保留；`option` / `placeholder` / `toast` 文案等无法渲染组件处去除 emoji（星级下拉保留单色 ★）

## 🛠️ 优化改进

- **归档失败不再静默降级**：普通下载归档失败此前会被当成"仅支持 H@H 画廊"而自动降级为画廊逐图下载（画质不达标、需再走质量升级），现一律报错可重试（`mode` 保持归档、不生成画廊目录）；**自动更新任务仍保留** `autoUpdateFallbackToGallery` 开关控制的降级，设置项说明文案同步为「仅对自动更新任务生效」
- **H@H 退避重试**：下载页请求失败先重试 2 次（1s / 3s），仍失败才报错并标注「可重试」，网络抖动不再固化为画质降级
- **日志分类**：由全文子串匹配 `[update]` 改为**行首标签位置化解析**，正文出现关键字不再把普通下载任务误分进「更新」分类
- **订阅页请求路径**修正为 `/watched`（原先错误路径导致 404，页面静默退回首页）
- **E-H tag 解析**只取规范 key，历史别名后缀脏数据自愈
- **书签卡片 UI 一轮迭代**：配置菜单被卡片 `overflow` 裁剪修复；封面渲染修复 + 封面引用迁移保留；标记三项切换与左侧色条；备注校验改按折算显示行数；分区按名称翻译排序（`Intl.Collator` 数字序）；uploader 无翻译时主标题回退显示上传者名
- **调度器回归用例补齐**：无界队列（1000 条不丢）、重启恢复（300 条不丢）、串行 / 并行优先级门控、归档并发窗口、调度发牌与资源释放、普通下载不降级 / 更新任务按开关降级
- **测试稳定性**：推荐随机源可注入并固定种子；忽略新增感知的毫秒时间竞态修正

## 🐛 Bug 修复

- **排队任务卡死「排队中」**：通道满即丢弃导致任务永不启动，必须手动「暂停 → 恢复」才有一批开始（实机 704 任务复现）——改无界队列
- **书签卡片配置菜单不可见**：卡内 `overflow` 裁剪导致置顶 / 标记 / 探测选项被截断
- **书签卡片封面渲染异常**与标记切换失效
- **订阅页 404 静默返回首页**
- **书签备注校验口径**：由字符数改为折算显示行数，避免中英文混排时超框
- **uploader 标题兜底**：标题翻译缺失时主标题直接显示上传者名

## ⚠️ 已知问题

- **更新探测依赖 E 站凭据**：未绑定或凭据失效的用户会被跳过并记录日志（不会误标红点）；探测为逐条串行、复用全局限流器，书签很多时会持续一段时间
- **创建书签的锚点转移是提示式**：同检索条件书签仅提示可转移，需手动确认，不自动替换
- **书签页极窄屏仍偏挤**：三列 → 两列（1100px）→ 单列（720px），<720px 时卡片较窄
- **「加载较新内容」锚点卡列位可能横跳一格**：E 站每页 25 张与列数不整除（v2.2.0 起既有，垂直位置精确保持，已接受现状）
- **维护页疑似重复 / 推荐算法**相关单测存在既有顺序性偶发失败，与本次改动无关
- 项目仍处于快速迭代期，可能存在未覆盖的边缘场景

## 📖 使用说明

- **Windows exe**：下载 `SakuManga.exe` 双击运行（单文件内嵌前端 + 后端 + 自定义图标），运行后最小化到系统托盘，右键托盘图标可选「打开界面 / 退出程序」
- **Docker（推荐 NAS / Linux 长期运行）**：

  ```bash
  docker run -d --name sakumanga --restart unless-stopped \
    -p 8081:8081 \
    -v /your/data/dir:/app \
    ghcr.io/yeonalbus/sakumanga:2.3.0
  ```

  镜像同时提供 `linux/amd64` 与 `linux/arm64`，标签策略 `2.3.0` / `2.3` / `latest`；数据（`manga.db` / `config.json` / `data/` / `logs/`）全部保存在挂载目录，升级 = 换标签重建容器。完整说明见 [`DSPlans/VerNotes/wiki.md`](wiki.md)「九、Docker 部署」
- **纯后端（NAS 无 Docker 环境）**：`SakuManga.exe --headless`
- 默认监听端口 `8081`（「设置 → E 站连接 → 网络」可改），被占用时自动切换空闲端口
- 首次启动自动创建管理员账号 `admin` / `admin123`，登录后请尽快在「账户」中修改
- **升级安装**：exe 方式直接替换文件；Docker 方式换镜像标签重建容器。数据均自动保留，数据库结构由启动时自动迁移（本版新增 `NetworkSetting` / `ArchiveBinding` 两张表与书签 9 个字段，另有一次书签字段回填，`fields_migrated` 标记保证幂等；**建议升级前备份 `manga.db`**）
- **高级代理**：为管理员新增设置项（「设置 → E 站连接 → 网络 → 高级」），默认关闭。开启需本机运行 Clash / mihomo 控制面（默认 `127.0.0.1:9090` 一类）并提供 `secret` 与代理组名；关闭时面板置灰、不影响既有网络设置
